## Evidence levels

- **Source-present:** code implements or exposes the recorded surface. This does not prove a test passed, a bundle contains it or the installed runtime uses it.
- **Marker-only:** a package carries a marker/string; that alone does not prove the full path works.
- **Partial:** only part of the intended capability is implemented/composed or important limits remain.
- **Requested-only:** product scope/backlog, not an implemented completed feature.
- **Runtime-verified:** requires an actual receipt tied to the exact tested artifact and stated environment. Do not infer it from any of the labels above.

The technical register preserves literal archived status labels and limitations. No entry is silently upgraded to runtime-verified by its inclusion in polished copy.

## Native editing boundary

The frozen source README targets pinned default `in_process` execution with the actual same-process serving owner. It reports positive saved-edit fixtures using synthetic canonical completion data and actual native policy-veto refusal.

That evidence does not establish:

- Genuine provider-positive saved editing.
- Active-provider cancellation/Stop correctness.
- Complete compaction, restart, approval and lifecycle behaviour.
- Native Electron visual and interaction acceptance.
- macOS or Windows execution.

Ordinary Address work applies the validated final proposal after confirmed completion. It does not stream writes through the registered tool. Host/detached execution without an admitted native owner refuses rather than changing mode or fabricating continuity.

## Context and recovery limits

- The native picker covers a bounded recent live/stored list, not complete older history.
- Address captures authorised content/comments. It does not automatically extract every attachment's content or infer necessity-aware sibling context.
- Related-item edit approval is not a separate broad read-only retrieval product.
- Stop revokes Workspace writes before requesting native cancellation. Local Recover can leave native execution uncertain; earlier accepted changes can remain.
- Section revert needs eligible change provenance and a safe mapping. Whole-item Restore and checkpoint recovery have different overwrite consequences.
- Canonical backup covers the Store graph, not native conversations/configuration/credentials, execution authority, frontend drafts/preferences or shared membership catalogues. Restore replaces data; it is not merge.

## Performance, privacy and security language

No measured load-time, memory, token, cost or latency improvement is claimed. Test-source presence is not passing test output; bounded synthetic tests are not proof of mathematical zero leaks or provider-level editorial quality.

Local storage is not encryption or OS-user isolation. Configured model providers may receive authorised document/comment context. Hash validation is not signing. No cloud collaboration, public sharing links or real-time multi-user editing is claimed.
